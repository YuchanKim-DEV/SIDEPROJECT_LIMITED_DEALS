# 실험 03: 가상 대기열 (온라인 오픈런)

손님이 한꺼번에 몰려도 주문 서버에는 감당할 수 있는 만큼만 보내고, 대기열을 건너뛴 주문은 막는지 본다.

## 구조
```
손님 → gateway(:8000) ─ Rate Limit(Redis) ─→ queue-service(:8081)  줄 서기, 순번, 입장권
                                        └→ order-service(:8082)  입장권 확인 후 주문
```
| 부품 | 하는 일 | 설정 |
|---|---|---|
| 줄 (Redis Sorted Set) | member=사용자, score=도착 순번(`INCR`). 다시 줄을 서도 자리 유지(`ZADD NX`) | `queue:{상품}:waiting` |
| 입장 스케줄러 | 1초마다 맨 앞에서 N명을 꺼내(`ZPOPMIN`, 원자적) 입장권 발급(`SET EX`) | `admit-per-second: 100`, `token-ttl-seconds: 300` |
| 스케줄러 잠금 | 서버가 여러 대여도 한 대만 입장시킴(`SET NX PX 900`) | `queue:scheduler:lock` |
| 순번 화면 | SSE로 1초마다 내 순번을 밀어줌 | `GET /api/queue/{id}/stream` |
| 입장권 확인 | 주문 서버가 주문 전에 대기열 서버에 물어봄(트랜잭션 밖, 연결 300ms·응답 500ms 제한). 응답이 없으면 받지 않음(fail closed) | `ENTRY_TOKEN_REQUIRED=true` |
| Rate Limit | 대기열: 사용자마다 초당 20(순간 40). 주문: 전체 초당 500(순간 1000). 넘으면 429 | gateway `RequestRateLimiter` |

## 다시 돌려보기
```bash
docker compose up -d
./gradlew bootJar
ENTRY_TOKEN_REQUIRED=true scripts/run-local.sh start --spring.jpa.show-sql=false
scripts/load/open-run.sh http://localhost:8000 50 300 300
scripts/run-local.sh stop
```
브라우저로는 `http://localhost:8000`의 테스트 콘솔에서 상품을 만들고, 줄을 서고, 가상 사용자 1만 명을 한꺼번에 줄 세워 볼 수 있다.

## 결과 (2026-11-05, 로컬)
| 실험 | 결과 |
|---|---|
| 손님 300명 동시, 재고 50 | 300명 모두 순서대로 입장, **구매 50건**, 품절 250건, 초과 판매 0 |
| 입장권 없이 주문 API 직접 호출 | **403** |
| 한 사람이 1초에 100번 연타 | 40번 통과, **60번 429** |
| 서로 다른 100명이 1번씩 | 100번 모두 통과 |
| 대기열 서버를 끄고 입장권으로 주문 | **503, 0.02초** (확인 없이 받지 않음), 재고 그대로 |
| 대기열 서버를 끄고 게이트웨이로 대기열 호출 | **500** ← 503이어야 한다. 5단계에서 고친다 |

## 왜 이렇게 했나
- **대기열이 왜 필요한가**: 1단계에서 재고 차감은 정확하게 만들었지만, 10만 명이 동시에 주문 서버로 오면 DB 커넥션(기본 10개)과 행 잠금 대기가 쌓여 응답이 느려지고 결국 무너진다. 대기열은 몰린 요청을 **Redis(메모리)에서 받아 줄만 세우고**, 주문 서버에는 1초에 정해진 인원만 보낸다.
- **왜 Redis인가**: 줄 서기와 순번 조회는 초당 수만 건이 몰리는데 DB에 쓰기엔 너무 잦고, 잃어도 다시 줄을 서면 되는 데이터다. Sorted Set이 "순서 + 내 위치"를 한 번에 준다. 반대로 주문처럼 잃으면 안 되는 데이터는 MySQL에 둔다.
- **fail closed**: 대기열 서버가 죽었을 때 확인 없이 주문을 받으면(fail open) 대기열을 건너뛴 사람이 재고를 가져간다. 오픈런에서는 공정성이 더 중요해서 거절한다. 대신 대기열 서버가 죽으면 판매도 멈춘다(가용성을 포기).

## 한계
- 입장권은 유효 시간 안에 여러 번 쓸 수 있다(구매 한도는 멱등 키와 재고로만 막는다). 1인 1구매가 필요하면 주문 성공 시 입장권을 지우거나, 사용자별 구매 이력을 확인한다.
- 사용자 구분이 `X-User-Id` 헤더라 위조할 수 있다. 9단계(인증)에서 로그인 사용자로 바꾼다.
- SSE 연결은 서버 메모리에 있다. 서버가 여러 대면 사용자는 처음 연결한 서버에서 받는다(상태는 Redis에 있어서 정확성에는 문제없다).
- 시간 측정은 손님마다 bash와 curl을 여러 번 띄우는 방식이라 서버 성능을 재는 숫자가 아니다. 6단계에서 k6로 잰다.
